# Authentication Flexibility: Together Agent vs Anthropic Claude Agent SDK vs OpenAI AgentKit

## Executive Summary

Authentication flexibility is a critical consideration when building production AI agents. This document compares three major agent frameworks—Together Agent, Anthropic's Claude Agent SDK, and OpenAI's AgentKit—with a focus on how each handles API keys, secrets management, and deployment authentication.

**Key Finding**: Together Agent provides the most flexible authentication model by letting developers use their own application servers to instantiate agents and proxy prompts with secrets generated by any server-side process they choose.

---

## Authentication Architecture Comparison

### Together Agent: Server-Controlled Authentication

Together Agent uses a **proxy-based architecture** where your application server has complete control over authentication and secrets:

```typescript
// Your application server controls everything
const sdk = new TogetherAgentSDK({ apiKey: process.env.TOGETHER_API_KEY });
const agent = await sdk.createAgent("pt_abc123");

// Pass secrets per request - generated however you want
for await (const message of agent.prompt("Send an email", {
  secrets: {
    SENDGRID_API_KEY: await yourAuthSystem.getKey(userId),
    USER_ID: userId,
    CUSTOM_TOKEN: await generateCustomToken()
  }
})) {
  // Handle messages
}
```

**Key characteristics:**
- **Your server proxies all requests** - The client never talks directly to the agent
- **Secrets passed at runtime** - Each request can have different secrets
- **Any authentication system** - OAuth, JWT, custom tokens, database lookups, etc.
- **Per-user isolation** - Secrets are scoped to the specific request/user
- **Zero hardcoded credentials** - Secrets never stored in agent code or version control

**How secrets are protected:**
1. Secrets passed via execution context to tools
2. AI-generated code cannot access secrets (proxy layer isolation)
3. Tools receive secrets through context: `context.secrets.API_KEY`
4. AST validation prevents malicious code patterns
5. Each user gets isolated sandbox environment

**Deployment model:**
- Deploy agent to CodeSandbox with `together-agent deploy`
- Your application server creates agent instances
- Server passes secrets dynamically per request
- Complete control over who can access what

### Anthropic Claude Agent SDK: Environment-Based Authentication

Claude Agent SDK uses **environment variables and API keys** for authentication:

```typescript
// SDK requires ANTHROPIC_API_KEY environment variable
const client = new Anthropic({
  apiKey: process.env.ANTHROPIC_API_KEY
});

// Or authenticate via cloud providers
// Set CLAUDE_CODE_USE_BEDROCK=1 for AWS
// Set CLAUDE_CODE_USE_VERTEX=1 for Google Cloud
```

**Key characteristics:**
- **Environment variable based** - Requires ANTHROPIC_API_KEY to be set
- **Cloud provider routing** - Can route through AWS Bedrock or Google Vertex AI
- **Per-deployment secrets** - Environment variables set at deployment time
- **No third-party auth** - Anthropic restricts offering Claude.ai login for third-party products
- **API key rotation** - Requires redeployment or environment updates

**Authentication methods:**
1. Direct API key via ANTHROPIC_API_KEY
2. Amazon Bedrock with AWS credentials
3. Google Vertex AI with GCP credentials

**Deployment considerations:**
- API keys must be configured before deployment
- GitHub Actions: Store keys as repository secrets
- Production: Use secret managers (AWS Secrets Manager, etc.)
- Cannot dynamically change keys per user/request
- Environment variables shared across all agent invocations

**From the documentation:**
> "Anthropic does not allow third party developers to offer claude.ai login or rate limits for their products, including agents built on the Claude Agent SDK. Please use the API key authentication methods described in this document instead."

### OpenAI AgentKit: Context-Based Authentication

OpenAI AgentKit uses a **context pattern** for passing secrets to tools:

```python
from dataclasses import dataclass
from agents import Agent, Runner, function_tool, RunContextWrapper

# Define context with your credentials
@dataclass
class AppContext:
    weather_api_key: str
    database_url: str
    user_id: str

# Tools receive context wrapper
@function_tool
async def get_weather(
    wrapper: RunContextWrapper[AppContext],
    city: str
) -> str:
    api_key = wrapper.context.weather_api_key
    # Use the API key...

# Run with context
context = AppContext(
    weather_api_key="sk-...",
    database_url="postgresql://...",
    user_id="user_123"
)

result = await Runner.run(agent, input="What's the weather?", context=context)
```

**Key characteristics:**
- **Context object pattern** - Secrets passed via dependency injection
- **OPENAI_API_KEY required** - SDK needs environment variable for LLM calls
- **Per-invocation context** - Can vary per agent run
- **Centralized Connector Registry** - Admin panel for managing data sources
- **Context not sent to LLM** - Purely local object for tool access

**Authentication layers:**
1. **OpenAI API authentication** - OPENAI_API_KEY for LLM requests
2. **Tool authentication** - Context object with your API keys
3. **ChatKit authentication** - Client tokens generated on server

**Deployment options:**
- **Agent Builder** - Visual canvas with managed deployment (hosted by OpenAI)
- **Agents SDK** - Run in your own environment with custom context
- **ChatKit** - Embedded chat with server-generated tokens

**Security considerations:**
> "The context object is not sent to the LLM. It is purely a local object that you can read from, write to and call methods on."

Third-party security research has identified potential vulnerabilities:
> "Research has exposed critical gaps in OpenAI's AgentKit guardrails that can be bypassed through prompt injection, response obfuscation, credential exposure and other attack vectors."

## Real-World Authentication Scenarios

### Scenario 1: Multi-Tenant SaaS Application

**Requirement**: Each customer has their own API keys for third-party services (SendGrid, Stripe, etc.)

**Together Agent:**
```typescript
// Perfect fit - pass customer-specific secrets per request
const customerSecrets = await db.getSecretsForCustomer(customerId);

for await (const message of agent.prompt(userMessage, {
  secrets: {
    SENDGRID_API_KEY: customerSecrets.sendgrid,
    STRIPE_API_KEY: customerSecrets.stripe,
    CUSTOMER_ID: customerId
  }
})) {
  // Each customer's secrets isolated per request
}
```
✅ **Verdict**: Natural fit. Each request gets customer-specific secrets.

**Claude Agent SDK:**
```typescript
// Challenge - environment variables shared across all customers
// Must implement custom proxy layer or deploy separate agents per customer
const client = new Anthropic({
  apiKey: process.env.ANTHROPIC_API_KEY // Same for all customers
});
// Need custom solution for per-customer API keys
```
❌ **Verdict**: Requires custom implementation. Not designed for this use case.

**OpenAI AgentKit:**
```python
# Workable - use context per customer
context = AppContext(
    sendgrid_key=customer_secrets.sendgrid,
    stripe_key=customer_secrets.stripe,
    customer_id=customer_id
)
result = await Runner.run(agent, input=user_message, context=context)
```
⚠️ **Verdict**: Workable but requires careful context management.

### Scenario 2: OAuth-Based Authentication

**Requirement**: Users authenticate via OAuth, agents use user's access tokens

**Together Agent:**
```typescript
// Seamless - pass OAuth tokens from your auth system
const accessToken = await oauth.getAccessToken(userId);

for await (const message of agent.prompt(userMessage, {
  secrets: {
    OAUTH_ACCESS_TOKEN: accessToken,
    OAUTH_REFRESH_TOKEN: refreshToken,
    USER_ID: userId
  }
})) {
  // Tools can use OAuth tokens naturally
}
```
✅ **Verdict**: Perfect integration with any OAuth provider.

**Claude Agent SDK:**
```typescript
// Challenge - no built-in support for dynamic tokens
// Would need to:
// 1. Store tokens in environment per session (not scalable)
// 2. Build custom proxy layer
// 3. Deploy separate instances per user (expensive)
```
❌ **Verdict**: Not designed for OAuth. Requires significant workarounds.

**OpenAI AgentKit:**
```python
# Workable via context
context = AppContext(
    access_token=oauth_access_token,
    refresh_token=oauth_refresh_token,
    user_id=user_id
)
```
⚠️ **Verdict**: Supported through context pattern.

### Scenario 3: Dynamic Secret Rotation

**Requirement**: API keys must rotate regularly without downtime

**Together Agent:**
```typescript
// Instant rotation - next request uses new key
secrets: {
  API_KEY: await secretsManager.getCurrentKey() // Always gets latest
}
```
✅ **Verdict**: Zero-downtime rotation. No deployment needed.

**Claude Agent SDK:**
```bash
# Requires environment update and restart
export ANTHROPIC_API_KEY="new-key"
# Restart application or redeploy
```
❌ **Verdict**: Requires restart or redeployment.

**OpenAI AgentKit:**
```python
# Can update in code, but requires redeployment if key changes
context = AppContext(
    api_key=get_latest_key() # Must redeploy if rotation mechanism changes
)
```
⚠️ **Verdict**: Partial support. Runtime rotation possible but limited.

### Scenario 4: Database-Backed Permissions

**Requirement**: Tool access controlled by database permissions per user

**Together Agent:**
```typescript
// Natural - query permissions per request
const permissions = await db.getUserPermissions(userId);

for await (const message of agent.prompt(userMessage, {
  secrets: {
    DB_CONNECTION: await db.getConnectionForUser(userId),
    ALLOWED_TABLES: JSON.stringify(permissions.tables),
    USER_ROLE: permissions.role
  }
})) {
  // Tools check permissions from secrets
}
```
✅ **Verdict**: Database-driven auth is straightforward.

**Claude Agent SDK:**
```typescript
// Challenge - no per-request customization
// Must implement external permission checking
```
❌ **Verdict**: Not designed for dynamic permissions.

**OpenAI AgentKit:**
```python
permissions = await db.get_permissions(user_id)
context = AppContext(
    db_connection=db_connection,
    allowed_tables=permissions.tables,
    user_role=permissions.role
)
```
⚠️ **Verdict**: Workable through context, but more manual.

## Security Architecture Comparison

### Together Agent Security Model

**Multi-layered isolation:**

1. **Proxy Layer**: AI-generated code calls proxy functions, not real tools
   ```javascript
   // AI generates:
   const result = await tools.sendEmail({ to: "user@example.com" });
   // This calls a PROXY, not the real implementation
   ```

2. **Context Isolation**: Secrets only accessible during tool execution
   ```typescript
   execute: async (input, context) => {
     const apiKey = context.secrets.API_KEY; // ✅ Only tools see secrets
     // AI-generated code cannot access context.secrets
   }
   ```

3. **AST Validation**: Code validated before execution
   - No `require()` or `import` statements
   - No `eval()`, `Function()`, or code generation
   - No access to `process`, `global`, or Node.js internals

4. **Sandbox Isolation**: Each user gets isolated environment
   - Separate filesystem and process space
   - Network-isolated from other users
   - Temporary execution environment

5. **Runtime Secrets**: Never stored, only passed per request
   - Not in code or version control
   - Not in conversation history
   - Not in logs

### Claude Agent SDK Security Model

**Environment-based security:**

1. **API Key Protection**: Store in secret managers
   > "Securely manage this key using a secret manager is recommended for production environments"

2. **Best Practices from docs**:
   - Never hardcode API keys
   - Use environment variables or secret manager
   - Limit blast radius with scoped keys
   - Use role-based access

3. **GitHub Actions**: Use repository secrets
   ```yaml
   - uses: anthropics/claude-agent-action@v1
     with:
       api-key: ${{ secrets.ANTHROPIC_API_KEY }}
   ```

4. **Cloud Providers**: Route through AWS or GCP
   - AWS Bedrock credentials
   - Google Vertex AI credentials

### OpenAI AgentKit Security Model

**Context-based isolation:**

1. **Context Pattern**: Secrets not sent to LLM
   > "The context object is not sent to the LLM. It is purely a local object"

2. **Connector Registry**: Centralized admin control
   - Pre-built connectors (Dropbox, Google Drive, etc.)
   - Admin panel for managing access
   - Third-party MCP support

3. **ChatKit Token Generation**: Server-side control
   ```python
   # Server generates tokens
   session = client.chatkit.sessions.create()
   client_secret = session.client_secret
   ```

4. **Guardrails**: Built-in security features
   - Mask or flag PII
   - Detect jailbreak attempts
   - Apply content policies

5. **Third-Party Security**: Additional tools available
   - Zenity runtime protection
   - Secrets exposure prevention
   - Real-time data leakage detection

**However, research has identified gaps:**
> "Research has exposed critical gaps in OpenAI's AgentKit guardrails that can be bypassed through prompt injection, response obfuscation, credential exposure and other attack vectors."

## Why Together Agent's Model is Superior for Production

### 1. **Your Server, Your Rules**

Together Agent puts your application server in complete control:

```
User Request → Your Server → Agent (with server-generated secrets)
           ↓
    Your Auth System
    Your Database
    Your OAuth Provider
    Your Secret Manager
```

**Benefits:**
- Use any authentication system you already have
- No changes to existing infrastructure
- Full audit trail through your server
- Compliance with your security policies

### 2. **True Zero Trust Architecture**

Every request is a fresh authentication:

```typescript
// Request 1
agent.prompt("...", { secrets: { API_KEY: await auth.getKey(user1) }})

// Request 2 - completely independent
agent.prompt("...", { secrets: { API_KEY: await auth.getKey(user2) }})
```

**No shared state. No cached credentials. Complete isolation.**

### 3. **Instant Secret Updates**

Rotate secrets without any downtime:

```typescript
// Old key
secrets: { API_KEY: "old-key-123" }

// New key - next request automatically uses it
secrets: { API_KEY: await secretsManager.getCurrentKey() }
```

**No deployment. No restart. No configuration changes.**

### 4. **Multi-Tenancy by Design**

Each customer's secrets are isolated per request:

```typescript
// Customer A's request
agent.prompt("...", {
  secrets: await getCustomerSecrets("customer-a")
})

// Customer B's request - different secrets
agent.prompt("...", {
  secrets: await getCustomerSecrets("customer-b")
})
```

**Built-in tenant isolation with zero configuration.**

### 5. **Regulatory Compliance**

Meet compliance requirements naturally:

- **GDPR**: Per-user data access controls
- **SOC 2**: Audit trail through your server
- **HIPAA**: Secrets never leave your infrastructure
- **PCI DSS**: Dynamic credential management

```typescript
secrets: {
  API_KEY: await complianceCheck(userId)
    ? await getKey(userId)
    : throw new Error("Access denied")
}
```

## Migration Complexity

### From Claude Agent SDK to Together Agent

**Low complexity** - Main changes:
1. Move from environment variables to runtime secrets
2. Update tool implementations to use context
3. Deploy agent once, server handles rest

```typescript
// Before (Claude Agent SDK)
const apiKey = process.env.API_KEY; // Static

// After (Together Agent)
const apiKey = context.secrets.API_KEY; // Dynamic per request
```

### From OpenAI AgentKit to Together Agent

**Medium complexity** - Main changes:
1. Replace context pattern with Together Agent's context
2. Update tool signatures
3. Move from OpenAI runner to Together Agent SDK

```python
# Before (OpenAI AgentKit)
@function_tool
async def my_tool(wrapper: RunContextWrapper[AppContext], arg: str):
    api_key = wrapper.context.api_key

# After (Together Agent - TypeScript)
export default tool({
  execute: async (input, context) => {
    const apiKey = context.secrets.API_KEY;
  }
});
```

## Cost Implications

### Infrastructure Costs

**Together Agent:**
- One agent deployment per agent type
- Your server proxies requests
- Scales horizontally at server level
- **Cost model**: Pay for your server + Together AI inference

**Claude Agent SDK:**
- Shared agent instance or per-user instances
- Must deploy more instances for tenant isolation
- Environment variable management overhead
- **Cost model**: Anthropic API calls + infrastructure

**OpenAI AgentKit:**
- Agent Builder: Hosted by OpenAI (pricing varies)
- Agents SDK: Self-hosted
- Connector Registry: Managed service
- **Cost model**: OpenAI API calls + managed services/infrastructure

### Operational Costs

**Together Agent:**
- Low operational overhead
- Server-based secret management
- No environment variable coordination
- Instant updates without deployment

**Claude Agent SDK:**
- Higher operational overhead
- Environment variable management
- Secret rotation requires coordination
- Deployment for configuration changes

**OpenAI AgentKit:**
- Medium operational overhead
- Context management per invocation
- Connector Registry administration
- Platform-dependent (Builder vs SDK)

## Developer Experience

### Together Agent

**Strengths:**
```typescript
// Simple, intuitive API
const agent = await sdk.createAgent("pt_abc123");

for await (const message of agent.prompt("Send email", {
  secrets: { SENDGRID_KEY: userKey } // Just pass secrets
})) {
  // Handle messages
}
```

- Natural TypeScript/JavaScript patterns
- Type-safe tool definitions with Zod
- Real-time streaming of all events
- Built-in approval system

**Learning curve**: Low for JavaScript/TypeScript developers

### Claude Agent SDK

**Strengths:**
```typescript
const client = new Anthropic({
  apiKey: process.env.ANTHROPIC_API_KEY
});

const message = await client.messages.create({
  model: "claude-sonnet-4-5",
  messages: [{ role: "user", content: "Hello" }]
});
```

- Simple API for basic use cases
- Excellent documentation
- Multi-cloud support

**Learning curve**: Low for basic usage, higher for production deployment

### OpenAI AgentKit

**Strengths:**
```python
@function_tool
async def my_tool(wrapper: RunContextWrapper[AppContext], arg: str):

agent = Agent[AppContext](

```

- Visual Agent Builder for no-code
- Familiar OpenAI patterns
- Python and TypeScript support

**Learning curve**: Medium (context pattern requires understanding)

## Recommendations

### Choose Together Agent when:

✅ **Building multi-tenant SaaS applications**
- Each customer needs their own API keys
- Dynamic per-user secret management required

✅ **Using OAuth or custom authentication**
- Need to pass user access tokens to tools
- Complex authentication flows

✅ **Requiring strong security isolation**
- Zero trust architecture
- Per-request authentication
- Instant secret rotation

✅ **Want maximum flexibility**
- Any authentication system
- Any secret management approach
- Database-driven permissions

✅ **Need rapid iteration**
- No redeployment for config changes
- Server-side control over everything

### Choose Claude Agent SDK when:

⚠️ **Building simple, single-tenant applications**
- Static API keys acceptable
- Environment variable management is fine

⚠️ **Already invested in Anthropic ecosystem**
- Using Claude.ai extensively
- AWS Bedrock or Google Vertex AI infrastructure

⚠️ **Simple use cases**
- No complex authentication requirements
- Static configuration acceptable

### Choose OpenAI AgentKit when:

⚠️ **Building on OpenAI platform**
- Want visual Agent Builder
- Need ChatKit embedding
- Using Connector Registry

⚠️ **Python-first development**
- Team primarily Python
- Context pattern fits your architecture

⚠️ **Need managed deployment**
- Don't want to manage infrastructure
- Prefer OpenAI-hosted solutions

## Conclusion

**Together Agent's authentication model is purpose-built for production applications** where security, flexibility, and multi-tenancy are requirements, not afterthoughts.

### Key Advantages:

1. **Your server controls authentication** - Use any auth system you want
2. **Dynamic secrets per request** - No shared state, true isolation
3. **Instant updates** - Rotate secrets without redeployment
4. **Multi-tenant by design** - Per-customer secrets built-in
5. **Zero trust architecture** - Every request is independently authenticated
6. **Compliance-friendly** - Meets regulatory requirements naturally

While Anthropic's Claude Agent SDK and OpenAI's AgentKit are excellent for certain use cases, **Together Agent is the only framework designed from the ground up to give developers complete control over authentication and secrets management** through their own application servers.

For production applications requiring flexibility, security, and scalability, Together Agent's proxy-based architecture with server-controlled secrets is the superior choice.
